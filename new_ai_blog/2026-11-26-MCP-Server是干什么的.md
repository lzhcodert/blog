你让 AI"把桌宠换成我家猫的花色"，它回你一段操作说明——因为它只能说话，没有手。MCP Server 就是给 AI 装上的那只手：一个让对话里的请求真正落到程序上的标准接口。

## 一个先能懂的类比

把 AI 客户端想成一台电脑，把文件、数据库、桌宠这些程序想成外设。以前每种外设都要配自己的驱动，电脑还得认识每个牌子；后来有了 USB-C，形状统一了，谁都能插。

MCP（Model Context Protocol）就是这个统一形状的插头：

- **Host**：你用的 AI 应用，比如 Claude Desktop、Cursor、WorkBuddy；
- **MCP Client**：嵌在 Host 里的那部分，负责把模型的话翻译成标准请求；
- **MCP Server**：某个程序暴露出来的接口，声明"我能做这几件事"；
- **工具（tool）**：Server 开放的具体动作，比如"列出猫咪皮肤""修改设置"。

模型不需要知道 KuroCat 的窗口长什么样，KuroCat 也不需要知道你用的是哪家模型。两边都只认 MCP 这套说法。

## 它到底解决了什么问题

没有 MCP 的时候，三个 AI 想操作四个工具，就要写十二套适配——每家 AI 都要为每个工具单独做一遍。有 MCP 之后变成三加四：AI 只实现一次客户端，工具只实现一次服务端，谁都可以接谁。

这才是 MCP 真正的价值：不是让模型更聪明，而是让模型的能力可以外接，而且一次接入处处可用。

## 拿 KuroCat 当例子

KuroCat 是一只开源桌宠：透明的、置顶的，你敲键盘它就做对应的按键动作，还带摸头呼噜、密码输入时自动捂眼、OBS 透明直播源。项目用 Rust 和 Tauri 做，安装包只有 2 MB 出头。

它比较特别的地方是把 **MCP Server 直接编译进了同一个可执行文件**。你不用另装 Node.js 或 Python，也不用单独部署一个服务。右键小猫，打开"开启 MCP 扩展"，复制配置贴进 AI 客户端，就能用对话捏猫。

两种连法，对应两种使用场景：

| 方式 | 怎么连 | 什么时候用 |
|---|---|---|
| stdio | AI 客户端启动 `KuroCat.exe --mcp`，通过标准输入输出通信 | 最通用，Claude / Cursor / Cline 等都能用，桌宠不必先打开 |
| 本机 HTTP | 连接 `http://127.0.0.1:27420/mcp` | 桌宠已经在跑，多个客户端可以连同一只猫 |

Stdio 配置长这样：

```json
{
  "mcpServers": {
    "kurocat": {
      "command": "C:\\Users\\<你的用户名>\\AppData\\Local\\KuroCat\\KuroCat.exe",
      "args": ["--mcp"]
    }
  }
}
```

HTTP 方式更短：

```json
{
  "mcpServers": {
    "kurocat": {
      "url": "http://127.0.0.1:27420/mcp"
    }
  }
}
```

注意地址是 `127.0.0.1`，也就是本机回环地址。它只在这台电脑上监听，不等于把服务暴露到公网。

## 一次"捏猫"请求发生了什么

假设你发一张三花猫照片，说"照它的花色、耳型和斑点捏一只 3D 桌宠并切过去"。底下大概走六步：

1. AI 识别出意图：这不是聊天，是要调用工具。
2. 先调 `get_cat_schema`，问清楚配置文件有哪些字段、16 处斑点坐标怎么填、7 项脸型耳型规范是什么。
3. Server 返回规范——**先看说明书再动手**，避免瞎猜参数名。
4. AI 按规范组装参数，调用 `upsert_cat` 提交新猫配置。
5. Server 写入 `cats.json`，桌宠热更新，大约 0.4 秒后新猫上屏。
6. Server 返回结果，AI 再告诉你"已经换好了"。

整套流程里，真正改变电脑状态的只有第 5 步，而且发生在本机。如果还要切换身份，再调一次 `switch_cat`，按 ID 切过去即可。

## 能力边界就写在工具清单里

KuroCat 一共暴露 10 个工具，分成四类：

| 类别 | 工具 | 能做什么 |
|---|---|---|
| 读 | `list_cats`、`get_cat_schema`、`get_settings` | 列皮肤、取规范、读缩放/键盘/气泡/呼噜声/穿透/自启等设置 |
| 写 | `upsert_cat`、`patch_cat`、`update_settings` | 新建或覆盖猫、局部微调、改设置，例如缩放到 85%、切 108 键面向观众 |
| 切换与清理 | `switch_cat`、`delete_cat` | 按 ID 切换、删除自定义猫或重置被改过的内置皮肤 |
| 联动与互动 | `set_agent_status`、`trigger_action` | 同步 AI 代理状态（思考/编码/执行/待确认/出错/完工），触发摸头、开心、生气、打瞌睡 |

这份清单很重要：**接入一个 MCP Server 之前先看它暴露了什么工具，你立刻就知道 AI 最多能做什么、改动范围多大**。这也是评估权限和安全边界最直接的办法。

自定义猫保存在 `%APPDATA%\kuro-cat-pet\cats.json`（Windows）或 `~/Library/Application Support/kuro-cat-pet/cats.json`（macOS），也可以手动编辑后热重载。

## 几个容易搞错的地方

**MCP 不是模型能力。** 它不提升推理水平，只是把模型的决定传给外部程序。模型判断错了，工具照样老实执行。

**不等于"装了就能改一切"。** 服务端只暴露声明过的工具，工具没开放的操作做不了。这既是限制，也是保护。

**stdio 和 HTTP 不是两套功能。** 它们只是两条传输通道，通向同一个 Server，工具清单完全一样。

**本地监听不等于绝对安全。** `127.0.0.1` 只对本机开放，但本机上的其他程序一般也能访问。真正要留意的是工具本身的权限范围，以及 AI 客户端是否会在你不知情时自动调用。

## 实战：让 WorkBuddy 连上这只猫

前面讲的是原理，这一节走一遍真实接入。WorkBuddy 是个合适的练手对象：KuroCat v5.1.2 起官方就支持与它联动，而且 WorkBuddy 把 MCP 配置做进了界面，不用手写文件也能接。

**第一步，让桌宠把"插座"露出来。**

运行 KuroCat，右键小猫 → 开启「**开启 MCP 扩展**」→ 点「**复制 MCP 配置**」。旁边还有个「发给 AI 自动配置」，偷懒的话用那个也行。

**第二步，在 WorkBuddy 打开配置入口。**

侧边栏进「**插件**」→ 右上角「**MCP 服务器**」→「**配置 MCP**」。WorkBuddy 会把配置直接显示在这个编辑器里，保存即可，不必自己去找文件。如果确实想直接改文件，两个位置对应两种作用域：

| 级别 | 文件 | 适合 |
|---|---|---|
| 用户级 | `~/.workbuddy/mcp.json` | 配一次到处能用，桌宠这种全局能力用它 |
| 项目级 | `<项目目录>/.workbuddy/mcp.json` | 只对当前项目生效，互不干扰 |

**第三步，把配置贴进去。**

Stdio 方式最通用，WorkBuddy 会自己拉起桌宠的 MCP 进程：

```json
{
  "mcpServers": {
    "kurocat": {
      "command": "C:\\Users\\<你的用户名>\\AppData\\Local\\KuroCat\\KuroCat.exe",
      "args": ["--mcp"]
    }
  }
}
```

注意 `command` 要换成你机器上 KuroCat.exe 的真实路径，JSON 里的反斜杠必须写成两个。

如果桌宠本来就在跑，用本机 HTTP 更省事，多个客户端还能连同一只猫：

```json
{
  "mcpServers": {
    "kurocat": {
      "url": "http://127.0.0.1:27420/mcp"
    }
  }
}
```

**第四步，看状态灯。**

保存后界面上会显示连接状态：绿色是连上了，红色说明配置、命令路径或地址有问题。这一步别跳过，很多"AI 没反应"其实只是红灯没注意到。

**第五步，用一句话验收。**

先来个不涉及捏猫的，验证工具确实通了：

> 把桌宠缩放到 85%，切换为 108 键面向观众视角，并关闭悬浮按键气泡。

以前这三步得自己右键点三回，现在一句话交给 AI。再进一步就可以发照片让它捏猫：

> 照这张我家三花猫的花色、耳型和斑点捏一只 3D 桌宠，然后切过去。

连不上时，按这个顺序排查：桌宠有没有开、MCP 扩展有没有勾、exe 路径是不是真实存在、JSON 的括号引号有没有漏、状态灯是红还是绿。绝大多数问题都停在前三项。

顺带提醒：配置里是 `127.0.0.1`，只在本机监听，不会把桌宠暴露到公网；但工具能改的东西不少，接好之后记得留意 AI 是不是在你没说话时也会自动调用。

## 你可以怎么试

如果你只是想理解 MCP 是什么，记住一句话就够了：**MCP Server 是把一个程序的能力，用标准方式介绍给 AI 的说明书兼遥控器。**
