缩写中文全称作用 / 说明
ODS操作数据存储层（Operational Data Store）数据仓库最靠近源系统的一层，存放经 ETL 抽取的原始数据快照，粒度最接近业务系统，供后续清洗加工。
DWD明细数据层（Data Warehouse Detail）对 ODS 数据做清洗、去重、规范化后形成的明细事实数据，统一口径，是进一步汇总的基础。
DWS汇总数据层（Data Warehouse Summary / Service）按主题对 DWD 做轻度汇总形成的汇总宽表，面向分析查询；数据集市从这里取数加工。
数据集市Data Mart面向特定业务（如营销）的小型数据仓库，从 DWS 取数加工成宽表/标签/模型，供 CRM 等应用"即取即用"。
ETL抽取-转换-加载（Extract-Transform-Load）把源系统数据抽取出来、按规则转换清洗、再加载到目标库的过程，是数据汇聚的核心手段。
CRM客户关系管理（Customer Relationship Management）银行客户经营的操作型系统，负责客户视图、精准营销、业绩看板等业务操作与策略执行。
ESF / ESB企业级微服务平台 / 企业服务总线（Enterprise Service Bus）统一的服务调用网关，负责路由转发、协议/报文转换、权限校验、流量控制。
OBS对象存储（Object Based Storage）信创对象存储，承载录音、语音转写、报告等非结构化数据，海量、低成本、可扩展。
MQ / Kafka消息队列 / 分布式消息中间件用于系统间异步消息传递，可触发 DataStage 作业或实现准实时数据推送。
DataStageIBM 数据集成 ET L 工具数据交换平台的核心 ETL 引擎，负责批量抽取、转换、加载与作业调度。
T+1交易日次日银行批处理常见口径，指当日交易数据在下一个交易日加工完成并可供使用。

三条通道对比

通道连接关系交互方式核心职责
① 实时服务调用 CRM ⇄ ESF/ESB ⇄ 目标微服务群 同步、实时 服务路由、协议/报文转换、权限校验、流量控制；秒级查询单个客户状态（准实时例外也走此通道，如 RocketMQ/API）。
② 批量数据流转 CRM → 数交 → 数据湖 → 数据集市 →（加工结果）→ 数交 → CRM 异步批量（ETL）
文件推送 + 解析落库		 双向摆渡：上报客户信息/交互记录入湖；再把集市加工好的画像标签、营销名单异步回供 CRM 落库。遵循"交易与批处理分离"原则。
③ 文件存储 CRM ⇄ 信创 OBS（API），库内仅留引用地址 API 调用 承载录音、语音转写、分析报告等非结构化数据，数据库只保存引用地址。

数据集市 → CRM：异步批量供数链路

① 集市批量加工数据集市从数据仓库取数，按计划（如 T+1）批量产出画像标签、营销名单
② 触发数交调度通过文件就绪 / 消息 / 调度平台依赖，触发 DataStage 作业序列
③ 异步推送数据数交将批量记录或数据文件推送至 CRM 数据库或指定目录
④ CRM 解析落库CRM 接收文件、解析并落库，供客户经理与营销场景使用

加工完成后如何触发数交调度（三种机制）

文件就绪触发 最常用

集市产出数据文件后，再生成一个空的触发器文件；DataStage 作业中的 Wait for File 阶段持续监测，发现文件即启动后续流程。稳健、易管理，适合 T+1 批量。

消息触发 准实时

集市完成后向 MQ / Kafka 发送消息，DataStage 通过 WebSphere MQ 阶段或 Kafka/JMS 适配器消费消息并触发作业。技术可行，适合时效要求高的场景。

调度平台触发 企业级

由 TASKCTL / iMOIA.SMS 等调度平台集中管理，通过 Agent 依据作业依赖关系触发，支持失败重试、告警与统一运维。

例外说明：并非所有取数都要"等一天"。对实时营销名单、风险预警等时效敏感场景，可通过 API 同步调用或 消息队列准实时推送补充——但这类交互通常发生在 CRM 与后端微服务（经 ESF/ESB）之间，用于查询单客户实时状态；数据集市的核心产出绝大多数仍以批量异步交付。

完整业务场景串联

客户经理在 CRM 点击「查看全景画像」→ 经 ESF/ESB 实时调用客户/账户微服务，秒级聚合返回； 交互行为数据经 数据交换平台 批量入湖 → 数据集市加工成画像标签/营销名单 → 再经数交异步回供 CRM 落库，用于优化次日营销； 过程中生成的报告或录音经 API 存入 信创 OBS，数据库内仅保留文件引用地址。

一句话概括：ESF/ESB 管"服务调用"的实时控制，数据交换平台管"数据流转"的双向摆渡（异步批量为主），信创 OBS 管"文件存储"的海量承载。
