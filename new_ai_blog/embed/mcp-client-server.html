三者关系1:1 连接两层与 JSON-RPC从零构建六步三种能力

1Host、Client、Server 各有分工 关系

Host 是你在用的 AI 应用；Client 是 Host 内部专门维护一条连接的组件；Server 是提供能力和数据的程序。模型只跟 Client 对话，Client 再去找对应的 Server。

关键：MCP 只规定 Client 与 Server 之间「怎么说话」，不规定 Host 怎么用 LLM。模型不认识 Server，Server 也不用知道是谁在调它。

2一个 Client 对一条连接，一个 Server 可服务多个 Client 连接

Host 每接一个 Server，就创建一个 Client，两者之间是专属连接（dedicated connection）。但一个远程 Server 可以同时服务很多 Client——「一对一」说的是连接，不是 Server 的容量。

类比：Host 像手机，Client 像手机上的一个个 App 图标，Server 像提供服务的服务器。一个 App 连一个服务，但同一台服务器可以被很多 App 访问。

3两层结构：说什么（Data）和怎么送（Transport） 协议

Data layer 用 JSON-RPC 2.0 定义消息格式；Transport layer 负责把消息送过去。换传输方式，消息内容不变——这正是 MCP 能同时支持本地进程和远程服务的原因。

典型流程：Client 先 tools/list 问有哪些工具 → 把清单交给模型 → 模型选中后 tools/call 带参数调用 → Server 执行并返回结果。

4从 0 到 1：六步写出自己的 Server 实战

以官方 Python SDK 为例（Python 3.11+，SDK 2.0+）。类型注解就是入参规范，docstring 就是说明，不用手写 JSON Schema。写完先用 Inspector 调试，再接进 AI 客户端。

为什么这么简单：SDK 从类型注解和 docstring 自动生成 inputSchema 与能力声明，你只需写「做什么」，协议握手、消息封装、参数校验都由 SDK 处理。

5Server 能暴露的三类能力 边界

工具（能做什么）、资源（能读到什么）、提示词（能复用什么模板）。每个能力都有对应的发现方法和执行方法，客户端先 list 再 use。

能力清单就是权限清单：接入别人的 Server 前先看这里，你就知道 AI 最多能做什么、会不会改数据。自己写 Server 时，也只暴露必要的工具。
