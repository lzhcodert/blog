上一篇写「锁到底在锁什么」，把并发里最含糊的词拆开。这篇拆另一个更常用的词：**IO**。

面试里常问「IO 密集型和 CPU 密集型有什么区别」，但很少有人先问一句：IO 到底指什么？多数人的答案是「读写文件、收发网络包」。这个答案不算错，但它漏了一大半，而且容易把差着六个数量级的事情混在一起谈。

先给一个更好用的定义：

> **IO 是数据跨过一道你控制不了速度的边界。**

三个词：数据、边界、**控制不了速度**。为什么强调最后这一点？因为 CPU 和内存的速度你大体能预期，纳秒级，而且稳定；一旦跨出边界，对面是磁盘、网卡、另一个进程、另一台机器——它什么时候给数据，你说了不算。

按这个定义，IO 就不该按「文件 / 网络」来分类，而该按**边界有几道**来分。

## 一、四道边界，把所有 IO 装进去

| 边界 | 谁和谁之间 | 典型成员 |
|---|---|---|
| 跨特权级 | 进程 ↔ 内核 | read、write、fsync、mmap 缺页、io_uring 提交 |
| 跨设备 | CPU/内存 ↔ 外设 | 块设备、字符设备、显存、MMIO 寄存器、DMA |
| 跨进程 | 进程 ↔ 进程 | pipe、socketpair、共享内存、eventfd、消息队列 |
| 跨机器 | 本机 ↔ 远端 | TCP/UDP、RDMA、iSCSI、NFS、对象存储 |

**第一道：跨特权级。** 你的程序想碰硬件，必须求内核代办。这一求一答就是一次系统调用：CPU 从用户态切到内核态，再切回来。代价不是「数据多」，而是**切换本身**——几百纳秒，看着不多，但一次请求要切好几回，几十万 QPS 下就是实打实的 CPU 开销。io_uring 的出发点就是把提交和完成放进一块共享内存环，让批量 IO 不用一次次切换。

**第二道：跨设备。** 这才是「真 IO」发生的地方。块设备一次至少一个扇区，有队列、能合并、会排序；字符设备一次几个字节，来了就处理。还有两个特殊成员：**MMIO**（把设备寄存器映射进地址空间，你「读写内存」其实是在跟硬件对话）和 **DMA**（设备自己把数据搬进内存，CPU 只下指令）。

**第三道：跨进程。** 管道、socketpair、共享内存、eventfd、消息队列、信号。同一台机器内部，数据从一个进程到另一个进程，照样要过内核——**共享内存是唯一的例外**，它把同一块物理页映射进两个进程，谁都不拷。

**第四道：跨机器。** TCP/UDP、RDMA、iSCSI、NFS、对象存储、消息队列。它们的麻烦在于**叠加**：iSCSI 是「网络上的块设备」，NFS 是「网络上的文件系统」，你以为在写本地盘，其实每一步都在等网络。

一句话记住：**越往外的边界，你越控制不了，代价越大。**

## 二、一次 read() 到底跨了几道

谁都写过这段代码：

```c
char buf[4096];
ssize_t n = read(fd, buf, sizeof(buf));
```

四行不到，但它跨了三道边界，动了两次切换、两次拷贝。

1. **你调用 read。** 参数是文件描述符、缓冲地址、长度，此时程序还在用户态。
2. **陷入内核。** 第一道边界跨了：特权级切换，进入 sys_read。
3. **先查页缓存。** 里面有这块数据吗？有，直接拷给你，一次盘都不碰——这就是「文件 IO 不等于磁盘 IO」的根源。
4. **没有就下块层。** 内核把请求合并、排序，组装成 bio 交给设备驱动。多个小请求可能被合成一个大请求，也可能被重排。
5. **设备干活。** 用 DMA 把数据写进页缓存。这一步 CPU 不搬字节，但它在**等**。
6. **中断唤醒。** 磁盘干完发中断，内核把睡着的进程叫醒——第二次切换，从睡眠回到运行。
7. **拷给你。** 数据从页缓存拷到你的 buf，read 返回。

所以一次未命中的 read，账是这么算的：**两次特权级切换 + 两次内存拷贝（设备→页缓存、页缓存→用户缓冲）+ 一段等设备的时间**。

命中页缓存呢？只剩最后一次拷贝，快三个数量级。缓存之所以有用，原因就在这。

## 三、那些没有「文件 / 网络」字样的 IO

- **MMIO**：`*(volatile uint32_t *)0xFE000000 = 1` 这行赋值，没有任何函数调用，却是一次真实的 IO——写的是设备寄存器。
- **DMA**：网卡收包、磁盘写盘、GPU 传纹理，数据由设备直接搬进内存，CPU 只负责下指令和收中断。
- **共享内存**：唯一不过内核的数据通道。两个进程映射同一块物理页，读写就是普通内存访问；代价是同步得自己做（信号量、原子变量）。
- **eventfd / 信号**：不传数据，只传「事情发生了」这个事件。严格讲这也是 IO——跨边界的通知。
- **终端与字符设备**：`printf` 到终端、读串口、读 GPIO，都是字符设备 IO。日志打太多会拖慢程序，拖慢的就是这条路径。
- **传感器与工业总线**：I2C、SPI、CAN，一次几十字节，延迟从微秒到毫秒不等。

这些例子的共同点是：**都没有「文件」或「网络」这两个词，但都在等一道边界。**

## 四、文件 IO 不等于磁盘 IO

性能讨论里最常见的错，就是把这两个词混用。它们中间隔着一层页缓存：

- **默认的 read/write 走页缓存。** 命中时根本不碰盘，是纯内存操作，微秒级。
- **O_DIRECT 绕过页缓存**，直接对设备发请求。数据库自己管缓存时这么干，因为它不想让数据被缓存两遍。
- **mmap 把文件映射进地址空间**，读文件变成读内存，只有缺页时才真正读盘。
- **块层还会合并与排序。** 所以「我发了 100 次写」和「盘上发生了 100 次写」是两件事，中间那一层会改写你的请求。

## 五、逻辑 IO 与物理 IO

数据库说「这个查询 800 次 IO」，八成是**逻辑读**：buffer pool 命中一次算一次逻辑 IO，一次盘都没碰。真正落到设备的才叫**物理 IO**。

这两个指标经常差一两个数量级。混着看，就会把内存命中当成磁盘压力，然后去扩容一块根本没在干活的盘。

## 六、零拷贝：拷贝少了，IO 还在

传统做法是 read + write 接力：数据从磁盘进页缓存（DMA），拷到用户缓冲（CPU），再拷到 socket 缓冲（CPU），最后由网卡发出去（DMA）。四次拷贝、四次切换。

sendfile 让内核直接把页缓存交给网卡，两次 DMA、零次 CPU 拷贝。RDMA 更进一步，网卡直接读写远端内存，CPU 全程不参与。

但要注意：**拷贝次数减少，IO 本身没有消失。** 数据还是要跨边界，只是不再绕用户态走一圈。

## 七、为什么加线程解决不了 IO 慢

因为「线程」解决的是「等待期间 CPU 闲着」的问题，而 IO 慢有三种原因：等设备、等网络、拷贝与切换。加线程只对第一种有点用，而且很快撞天花板——线程栈默认 8MB 虚拟内存，一万个线程就是调度器和内存的双重负担。

真正要分清的是「怎么等」这一维：

| 模型 | 怎么等 | 谁来拷数据 | 适合 |
|---|---|---|---|
| 阻塞 | 睡过去，醒了继续 | 内核拷给你 | 连接少、逻辑简单 |
| 非阻塞 + 轮询 | 反复问「好了没」 | 你自己拷 | 几乎不用，白烧 CPU |
| 多路复用 | 一个线程等一堆 fd | 你自己拷 | 高并发网络服务 |
| 信号驱动 | 内核好了通知你 | 你自己拷 | 少见 |
| 异步 | 提交完就走，内核全办完再通知 | 内核拷好 | 高吞吐、低延迟 |

两个维度别混：**「是什么 IO」看边界，「怎么等」看模型。** 同一个 socket，可以阻塞读，可以 epoll，也可以 io_uring，对象没变，只是等法变了。

## 八、延迟阶梯：六个数量级

内存访问 100 纳秒，跨地域网络往返 50 毫秒，中间差了五十万倍。这张图解释了几条经验法则：

- **缓存为什么有用**：省掉的不是计算，是整整一道边界。
- **批量提交为什么有用**：把 N 次切换摊成一次。
- **跨机房调用为什么要谨慎**：一次往返的时间，够内存访问几十万次。

## 九、术语小抄

- **系统调用**：用户态请求内核代劳的唯一入口，一次调用两次特权级切换。
- **页缓存**：内核替文件内容维护的内存副本，命中就不用碰盘。
- **块层**：内核里管块设备的中间层，负责合并、排序、限流。
- **bio**：块层描述「要读写哪几个扇区」的结构，最终交给驱动。
- **DMA**：设备直接访问内存，CPU 不搬字节。
- **MMIO**：把设备寄存器映射到地址空间，读写它等于跟硬件对话。
- **零拷贝**：数据不进用户态，省掉 CPU 拷贝；不等于没有 IO。
- **逻辑 IO / 物理 IO**：缓存命中算一次逻辑读 / 真正落到设备。
- **io_uring**：用共享内存环提交与收割 IO，减少系统调用次数。
