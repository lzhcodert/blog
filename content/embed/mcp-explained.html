1通用插座：谁想用，就按同一个标准接 是什么

MCP 定义了一套统一说法：客户端说「我要调用哪个工具、参数是什么」，服务端照做并返回结果。AI 客户端不必认识每个应用，应用也不必为每个 AI 写插件。

类比：MCP 就像 USB-C。AI 客户端是电脑，MCP Server 是外设，协议是那个统一形状的插头。插头一样，谁都能接。

2它解决的真正问题：N×M 变成 N+M 为什么需要

没有统一协议时，每个 AI 要为每个工具单独适配；有了 MCP，每个 AI 只实现一次客户端，每个工具只实现一次服务端。

关键点：MCP 不是让 AI 更聪明，而是让 AI 的能力可以「外接」。工具越多，这个乘法效应越明显。

3KuroCat 的两种接法：stdio 与本机 HTTP 怎么连

两条路都通向同一个 MCP Server。左边由 AI 客户端启动一个子进程，通过标准输入输出通信；右边直接连接桌宠已经在跑的本机服务。

为什么给两种：stdio 最通用，任何 MCP 客户端都能用；本机 HTTP 更适合桌宠已经开着的场景，多个客户端可以连同一个桌宠。两者都只在本机通信。

4一次「捏猫」请求是怎么走完的 时序

纵轴是时间。你看不到 JSON，但它确实在底下按这套顺序跑了一遍：先看懂规范，再提交配置，落盘后热更新，最后切到新猫。

要点：第 ②③ 步是「先看说明书再动手」，避免瞎猜参数名。第 ⑤ 步是唯一真正改变电脑状态的一步，而且发生在你自己的机器上。

5KuroCat 暴露的 10 个工具，其实分四类 能力边界

MCP Server 的能力不是无限的：它只能暴露自己声明过的工具。KuroCat 这 10 个工具，正好定义了 AI 能对桌宠做的事的上限。

看工具清单的价值：接入一个 MCP Server 前先看它暴露了什么工具，就知道 AI 最多能做什么、改动范围有多大——这是评估权限和安全边界最直接的方式。
